## Smooth Samples - Project Brief

### 1) Absolute Priority Rule (Above All)
I am a beginner user.
Communicate in a clear, simple, and understandable way.
Do not take any initiative without my explicit confirmation.
If you have doubts, ask before proceeding.

### 2) Project Goal
Build a website to sell music sample packs across multiple styles and genres.

Primary competitors:
- Prime Loops
- Black Octopus
- ModeAudio
- Splice
- Boombap Factory

### 3) Brand Naming
Primary brand name: **Smooth Samples**.
If this name is already in use or legally risky, suggest alternatives that must include the word **"Smooth"**.

### 4) Non-Negotiable Requirements
- Website language must be **English only**.
- Website must be **fully responsive** and work across modern browsers.
- Every sample pack must include a **dedicated audio preview player**.
- Audio previews must be delivered with anti-abuse protection to reduce easy downloading/extraction.
- Preview quality must be balanced: good enough for listening, not suitable as production-ready source material.
- Users must be able to browse and listen to previews **without logging in**.
- Account creation/login should support common methods (for example Google and major social providers).
- UI must be clean, modern, and UX-friendly.

### 5) General Best-Practice Rules
- Security first: enforce HTTPS, secure authentication flows, and input validation.
- Privacy and compliance: provide clear privacy policy, terms, and cookie handling.
- Performance: optimize media delivery, loading speed, and mobile performance.
- Accessibility: follow core accessibility standards (semantic structure, keyboard support, contrast, alt text).
- Scalability: structure catalog, tagging, and filtering for future growth.
- SEO fundamentals: semantic pages, metadata, and clean URL structure.
- Analytics readiness: track key events (preview plays, signups, conversions) with privacy-aware setup.
- Maintainability: keep code modular, documented, and consistent.

### 6) Audio Preview Protection Guidelines
- Do not expose full-quality original files in the frontend.
- Use short/limited preview versions only.
- Prefer streamed/chunked delivery with time-limited access controls when possible.
- Add deterrents against direct file scraping (signed URLs, token checks, rate limits).
- Accept that complete prevention is impossible on the web; target practical risk reduction.

### 7) Collaboration Workflow
- Before any implementation step, explain the plan in simple terms and wait for explicit approval.
- When multiple options exist, present concise alternatives with pros/cons.
- Ask clarifying questions whenever requirements are ambiguous.
- Never proceed on assumptions when a decision can change scope, cost, or architecture.
